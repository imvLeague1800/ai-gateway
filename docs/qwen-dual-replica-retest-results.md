# 双 Qwen 路由补测报告

复测日期为 2026-11-23（Asia/Shanghai）。被测入口为隔离 vLLM Router，模型为 `qwen3.6-35b-a3b-nvfp4`，后端为 Spark `.15` 和 `.16`。`.16` 已由 Gemma 切换为 Qwen。按本次要求保留 Qwen，原 Gemma 配置快照保存于 `.16:~/spark-vllm/reports/dual-qwen/retest-20261123/`。

## 固定配置和数据

- Router 为 `vllm/vllm-router:v0.1.17`，镜像摘要 `sha256:1128e09f5dc92b201753bc2f306488942d608ec747410f6c207354f0bf377c42`。两策略采用相同的健康检查间隔 5 秒、超时 3 秒、失败和成功阈值均为 2。缓存阈值 0.3，负载绝对差阈值 2，相对比阈值 1.2。
- 两台引擎镜像 ID 均为 `sha256:1d858604eba132f111f73bc9ff78fb9f9be2b27041a83eafc73885fded69b3c7`，启动参数一致。256K 上限，TP=1，最大并行序列数 4，每批至多 8,192 token，开启前缀缓存。两台的 tokenizer、tokenizer 配置与聊天模板在实机重算哈希匹配。沿用前轮权重校验，两个清单中的 17 个 Qwen 文件条目逐项一致。
- 两台引擎的 `/get_load` 均返回 404。隔离 Router 的决策日志显示使用本地在途请求数。所有正常回放请求经双副本 Router。热副本强制对照有单独的固定路由入口。
- 合成测试集 v1.0.0，共 300 个用例、195 个独立会话。高载与轻载各运行相同的 40% Agent、30% QA、30% RAG 请求构成。稳定前缀每轮 20 个 RAG 和 20 个 Agent 双轮会话。Agent、RAG 正式请求关闭 thinking，所有场景最多输出 1,024 token。
- 冷 Agent/RAG、续轮和 QA 的前轮 TTFT 预算分别为 10、5、2 秒。完成预算取校准轮各类 P95 向上取整到整秒。QA 15 秒，冷/续轮 Agent 21/17 秒，冷/续轮 RAG 16/17 秒。校准轮 60/60 通过，峰值有 17 个等待请求。校准 Agent 和 RAG 使用部分正式任务的合成变体，未达到严格任务级隔离；校准 RAG 约 17.7K token，正式 RAG 约 16.4K。
- 请求依赖按冻结的历史响应和工具结果推进。后续请求等待父请求结束和固定间隔，实际整体到达率可能因策略而变。高载名义 3.0 req/s，轻载 1.5 req/s。固定窗口为名义请求数除以对应请求率，再加冻结的 45 秒依赖尾窗。窗口外请求仍计入总体样本，窗口内实际发送并最终达标的请求用于计算固定窗口达标 req/s。
- 回放以首个实质 content 或工具增量记 TTFT，记录完整流结束、完成时间、质量和互斥主状态。P50/P95/P99 取排序后零基索引 `round(p*(n-1))` 的观测值。缓存比例按两引擎的 hits 增量合计除以 queries 增量合计。请求级缓存命中覆盖只接受请求级证据。

## 前轮口径勘误

保留 [前轮报告](qwen-dual-replica-test-results.md) 和原始记录。前轮 `power_of_two` 的 0% 是请求级缓存命中 token 比例的中位数。前轮高载总计 4 组，每策略每组 50 个请求，TTFT 达标数分别为 140/200 和 182/200。原 1.673 与 2.612 req/s 使用包含排空的时长。按前轮各组 `50 / 3.0` 秒的计划发送窗重算，固定窗 TTFT 达标率为 2.10 与 2.73 req/s。两个数值均为前轮固定窗口内的达标吞吐。

## 高载验收

三组配对各 300 请求，两策略各累积 900 请求，均 900/900 执行成功并通过评分。三组及合并结果均满足 P99、固定窗口完整达标吞吐和执行失败率护栏。合并 TTFT P99 从 44.707 秒降到 29.407 秒（−34.2%），完成 P99 从 45.638 秒降到 31.576 秒（−30.8%），固定窗口完整达标吞吐提高 27.7%。固定发送窗每轮 145 秒。六轮在途负载均形成引擎排队，且各轮累计缓存查询 token 数均与该轮响应中的 prompt token 总数一致。第一轮 `power_of_two` 的 1 个续轮在发送窗口之后发出，保留在 300 个评分样本中。各轮实际发送速率、等待队列和排空数据见附表。

## 轻载对照

三组配对共 1,800 请求，无 429、HTTP 错误、超时或断流。`cache_aware` 质量通过 900/900，`power_of_two` 质量通过 899/900，其中第一轮 QA `qa-085` 返回 `4`，预期为 `3`。合并后 `cache_aware` 的 TTFT P99 下降 13.4%，固定窗口完整达标吞吐变化约 +0.1%。

## 稳定前缀验收

每策略、每组包含 20 个 RAG 和 20 个 Agent 双轮会话。三个配对中，续轮 P95 分别改善 20.4%、20.6% 和 20.6%，合并从 2.674 秒降至 2.128 秒（−20.4%）。合并实际缓存命中 token 占比从 28.1% 升至 44.9%，各组缓存比例均提升。两个策略各 240 请求，全数成功并通过评分。

可完整归因的 120 个续轮中，`power_of_two` 有 78 个可归因，其中 48 个与父轮同副本。 `cache_aware` 有 71 个可归因，全部与父轮同副本。第一组在流结束后采样派发计数，归因覆盖较低。第二和第三组提前到收到响应头时采样。计数器并发变化无法归因的续轮保留为未知。请求级缓存命中比例未验证，汇总只使用引擎缓存 token 计数。

## 故障验收

对 `.16` 分别以两种策略各进行 3 次 Docker 停启。6 次都在 20 秒内摘除，范围为 8.95–10.22 秒。摘除后的 120 个探针均成功由唯一仍运行的 `.15` 服务。两台均在恢复后接到请求，6 次取消后 Router 两副本在途计数均为 0。故障窗口包含摘除前探针和发起停止前的在途流。以执行失败计，`power_of_two` 为 6/72，均为 HTTP 200 后断流。 `cache_aware` 为 7/72，包括 5 次断流和 2 次 HTTP 错误。另有 6 和 7 个流触发 1,024 token 截断，单独计入不完整结果。

`power_of_two` 的三次恢复均达标，引擎健康后首次重新接单为 6.48–17.84 秒。 `cache_aware` 两次通过，一次超时。第三次引擎对直连 `/health` 返回成功后，Router 健康状态仍持续为 0，26.78 秒后才转为健康，31.24 秒后证实重新接单。日志未提供这一轮的逐次探测结果，暂无法确认健康状态滞后的原因。恢复阶段如果 20 个顺序探针只覆盖一台，追加独立的 8 请求短突发确认两台均可接单。
