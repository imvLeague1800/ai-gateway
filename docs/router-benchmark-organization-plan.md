# Router benchmark 整理执行计划

日常 benchmark 继续分成 **smoke** 和**压测**两组。实机故障演练在压测组下保留独立的手动入口，分单次和多次两种模式。复用当前用例、探针、客户端和统计脚本。使用说明统一维护在 [benchmark README](../benchmarks/router/README.md)。

验收以真实服务的运行结果、日志和归档为准。日常 smoke 和压测发实际请求，实机故障演练使用真实停启。

## 1. 日常 smoke

- 每轮跑一遍现有非故障检查。保留 16 会话、28 请求、显式模型映射、独立问答、Agent 工具调用、稳定前缀续轮、RAG 召回变化，以及短队列和取消检查。候选策略默认使用 `cache_aware`。
- 从默认入口移除代理故障阶段。日常 smoke 不切换代理健康状态，也不停止 Qwen。同步更新摘要和分析，确保省略故障阶段时仍能准确报告各非故障阶段的结果。
- 服务就绪后记录整组及各阶段耗时，目标不超过 10 分钟。

## 2. 日常压测

- 保留全量路由回放、单机 1–4 路并发和长冷 RAG。全量回放走真实隔离 Router，单机并发直连实际 Qwen，长冷 RAG 通过临时 Scheduler 请求实际 Qwen。沿用现有压测入口、场景选择和统计口径。
- **全量回放失败须传到压测入口。** 任一轮回放子进程返回非零退出码时，`run_retest.py` 须先将该轮的组号、负载场景、Router 策略、原始退出码和日志路径写入本轮 `run-index.jsonl`，然后保证自身最终返回非零退出码。即使后续回放成功，也须保留已发生的失败。`run_stress.py` 须将 `replay` 阶段和整组压测标记为失败，写入顶层摘要后返回非零退出码。摘要保留 `replay` 阶段退出码和日志路径，能据此定位本轮索引及失败轮次的日志。
- **所有选中场景都须有本轮有效结果。** 入口拒绝重复的 `--modes` 和已存在的运行输出目录，独立场景入口也使用新输出目录。回放核对预期轮次及实际结果文件，单机并发和长冷 RAG 核对各自预期轮次及本轮摘要。仅在子进程退出码为 0 且结果完整、可解析时通过。缺少文件或结果无效时保留失败轮次、原因和日志路径，顶层返回非零。未选中的场景与命令预览均不计入实测通过。
- **长冷 RAG 核对本轮 Scheduler。** 启动前检查本地端口 `18080` 是否已占用。等待就绪时同时确认本轮启动的进程仍存活。端口冲突、进程提前退出或就绪超时均判失败并记录日志。
- 常规压测只运行非故障场景，运行全部场景也不会触发停启。与 smoke 或实机故障演练共用同一组 Spark 时串行执行。

## 3. 手动实机故障演练

| 模式 | 执行范围 |
| --- | --- |
| 故障 smoke | 真实停止并恢复 `.16` 的 Qwen 服务一次，验证一个完整周期。 |
| 多周期故障测试 | 使用同一个执行入口和同一套判定，重复停止并恢复 `.16` 的 Qwen 服务。由手动请求指定次数，每个周期独立记录。确认上一周期已恢复接单后才开始下一周期。 |

- **手动触发。** 用户确认维护窗口并明确要求执行后，agent 使用已实测能停启 Qwen 的 `dgx@10.169.25.16` 账号运行独立入口，传入 `--maintenance-window-ack` 和指定的周期数。移除 Compose dry-run、Docker socket/组和 sudo 权限推断以及 `--authorization-record` 分支。手动流程见 [.16 Qwen 实机演练方案](router-fault-drill-authorization.md)。
- **只读预检。** 核对 SSH 登录、目标 Qwen 服务和模型、两台引擎直连健康，以及隔离 Router 的就绪状态。若本次演练需要启动隔离 Router，在基础只读检查通过后单独启动再确认就绪。仅运行预检时不重建 Router。维护窗口未确认、登录或状态查询失败、目标不符、服务未就绪时，返回非零退出码并说明原因。预检期间真实 `stop` 和 `start` 的调用次数均为零。
- **操作范围。** 只停启 `.16` 的 Qwen 服务，`.15` 的 Qwen 和网关持续运行。使用两台 Qwen 直连的隔离 Router，默认策略为 `cache_aware`。故障和恢复期间保持同一 Router 容器与健康检查参数。复用 Git 历史中的实机周期逻辑和当前探针，固定目标为 `.16`，勿沿用旧矩阵对 `.15` 的停启能力。
- **恢复责任。** 发出停止命令后，发生探针失败、超时或其他异常时也尝试启动 `.16`，记录原始错误和恢复结果。SSH 或服务状态无法确认时判失败。未确认恢复时停止后续周期，立即报告实际状态。每次使用新 run ID，校验本轮执行退出码和摘要。
- **限制停机验证耗时。** 给摘除后的改派探针和在途请求收集设统一总时限。达到时限时保留已采集证据、标记本周期验证不完整并立即进入恢复，避免逐请求等待推迟启动 `.16`。该时限与恢复后 20 秒接单指标分别记录。

### 每个实机周期的验收

1. 停止前确认两台引擎直连健康，并记录至少一条经 Router 由 `.16` 完整返回的请求。若布置了在途探针，按实际落点记录完成或断流，包括 HTTP 200 后断流。
2. 记录停止命令结果和服务状态，确认 `.16` 直连健康检查失败。记录 Router 摘除耗时，沿用从发出停止命令起算的 20 秒目标。摘除后，所有探针均须由 `.15` 完整返回。
3. 记录启动命令、首次观测到 `.16:8000/health` HTTP 200 的时刻、Router 重新接纳时间，以及恢复后由 `.16` 完成的首条经 Router 的请求。用同一单调时钟计算“首条完整响应结束时刻减去首次直连健康时刻”，结果须 **≤20 秒**。健康探测任务在首次看到 200 时保存时间戳，即使启动命令尚未返回也沿用该时间戳。分别报告启动到直连健康的耗时，以及直连健康到完整接单的耗时。证据保留两个时刻、请求 ID、实际落点和流完成状态。任一时刻缺失、无法归因到 `.16`、响应不完整或超过 20 秒，均判该周期失败。
4. 演练结束确认两台引擎健康，且 `.16` 已通过 Router 实际接单。任何周期缺少关键证据、本轮执行失败或恢复未确认，整次演练返回非零退出码。

## 4. 交付与归档

- **已删除的旧诊断脚本。** `hot_forced.py` 和 `cold_rag/config_probe.py` 已从当前执行面移除，历史结果依照第 5 节归档。
- **收敛 smoke 可选参数。** 保留 `--baseline` 时，其子进程和摘要判定必须纳入顶层结果。保留 `--no-restart` 时，必须核实实际运行的 Router 策略，无法确认或与所选策略不符时拒绝。如果这两个参数没有现行用途，删除对应分支和用法即可。
- **统一文件哈希口径。** 固定 manifest 登记文件和 `smoke.json` 来源哈希的换行处理，避免 CRLF/LF 检出差异导致回放启动失败。更新当前指纹后，用干净检出核对整条哈希链。历史证据清单仍用原始字节哈希。

- 修复后由执行 agent 使用新 run ID 实际跑一次**日常 smoke**，从 benchmark 目录执行 `python run_smoke.py --policy cache_aware --run-id <新ID>`。记录命令、阶段结果、耗时、退出码和摘要路径。验收要求核心回放、排队与取消、分析均通过，整组退出码为 0，结果无代理或实机故障阶段。真实停机 smoke 仍按第 3 节单独手动触发。
- 按本轮选定的压测场景实际发请求，登记 run ID、各阶段退出码、摘要和日志。实测遇到回放子进程失败时，按第 2 节核对失败轮次和顶层退出码。未运行的压测场景，以及未在实测中出现的异常路径，按实际情况登记。
- 更新 [benchmark README](../benchmarks/router/README.md)，写清日常入口、手动入口、登录权限、单次和多次参数、结果路径及失败恢复方式。
- 删除现有 benchmark 的 mock 故障实现、用例及其调用，移除旧故障模拟和替身用例在 benchmark 执行清单、用法和验收步骤中的引用。历史 mock、代理和实机停启的结果归档继续保留。旧矩阵记录见 [双 Qwen 补测](qwen-dual-replica-retest-results.md)，代理记录见 [整理结果](router-benchmark-organization-results.md)。
- 在 [整理结果](router-benchmark-organization-results.md) 登记实际运行的命令、run ID、逐周期摘要和验收证据。尚未收到手动演练指令时，将实机验证标记为待执行。

## 6. 本轮收尾与静态验收

本轮执行范围以本节为准。执行 agent 完成代码和文档收尾、旧证据的持久归档及引用修正。验收只做静态代码审查、Git 树检查、文件清单和哈希核对。不要运行单测、smoke、压测、实机停启或离线复算，也不要连接 Spark。前文的实跑、干净检出运行和离线复算要求留待另行安排，结果报告中明确区分已有实测证据和本轮静态验收。

| 剩余问题 | 静态验收标准 |
| --- | --- |
| `.16` 停机验证仍可能拖延恢复 | 改派探针和在途请求收集共用一个明确的总时限，不叠加逐请求等待。时限到了就保留已采集的证据，标记本周期验证不完整，并进入恢复分支。发出停止命令后，异常路径也须尝试恢复。这个时限与首次直连健康到首条完整接单的 20 秒指标分别记录。 |
| 重复模式、旧目录和缺失结果可能造成压测误报 | 顶层在启动任何子进程前拒绝重复的 `--modes` 和已存在的输出目录，独立场景入口也拒绝已有输出目录。回放核对预期轮次和实际结果文件，并发及长冷 RAG 核对预期轮次和本轮有效摘要。即使子进程退出 0，只要结果缺失、无效或不完整，顶层也须返回非零，保留失败原因、轮次和日志路径。未选场景与命令预览不计为实测通过。 |
| 长冷 RAG 可能把其他 Scheduler 当成本轮进程 | 启动前拒绝本地 `18080` 端口占用。等就绪时检查本轮启动的进程仍存活，进程提前退出或超时须失败并保留日志。清理仅操作本轮启动的进程。 |
| 旧证据只落在本机 Git 忽略目录 | 把已迁出的 11 轮作为整轮归档复制到可访问的持久存储。从持久副本逐文件核对本地迁移源的 SHA-256、文件清单、数量和字节数，记录归档位置和校验结果。保留本地副本，直到持久副本验证完成。若持久位置不可用，报告待办，暂缓进一步移除。此前与 Git 比较发现的 LF/CRLF 差异沿用原核对记录，迁移校验使用本地源文件的原始字节。 |
| 旧引用未更新，保留项需要复核 | 更新 benchmark 主 README、`runs/README.md`、整理结果及旧 smoke 报告中仍指向已删目录的引用。用可访问的持久归档位置或归档索引加 run ID 定位历史证据。用 Git 文件清单核对第 5 节的当前验收证据和 `verify_archives.py` 的三个输入目录都保留，不执行复算。 |

Smoke 可选参数和 LF 归一化哈希已完成。本轮只核对相关代码与当前清单，若改动了清单登记的文件，同步更新 manifest 和 `smoke.json` 的来源哈希。交付时在整理结果中逐项注明已完成、未完成和未验证，附代码位置、归档位置或索引。
