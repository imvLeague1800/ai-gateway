## 3. 修复客户端异常漏计

当前长冷回放将 `asyncio.gather` 返回的异常标记为 `client_exception`，把场景写成 `unknown`，并把开始时间写成 `window_end`。运行汇总和离线分析都使用右端排他的窗口筛选，因此这些异常会掉出统计。 [回放代码](../benchmarks/router/cold_rag/cold_rag_replay.py:263) · [离线分析](../benchmarks/router/cold_rag/analyze_cold_rag.py:55)

- 创建任务时保留原用例 ID、场景、轮次、计划发送时间。到达发送点时记录实际开始时间。客户端异常生成一条带这些字段的失败记录，保留实际失败时间，TTFT 和输出速度保持未知。
- 同一套窗口归属函数供运行汇总与离线分析使用。有实际发送时间的记录按实际发送时间归属。发送前失败而没有这个字段时，按该请求的计划发送时间归属。窗口使用 `[window_start, window_end)`。窗口内异常进入该场景的请求分母，且只计一次执行失败。预热和窗口外异常另外留档。旧记录缺时间时标记无法归属，并报告其数量。
- 用现有 mock 测试补一条具体回归，覆盖窗口内客户端异常、发送前异常和窗口边界，并断言在线汇总与离线重算得到一致的分母、失败数和场景归因。
